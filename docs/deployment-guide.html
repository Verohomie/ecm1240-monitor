ecm1240-monitor — Deployment Guide

Version 1.0 Updated: 2026-07-28 Scope: wiring → install → verification → live Time: 2–3 hours, plus an electrician if needed
Read this before you open anything
This project needs current transformers installed inside a live electrical panel. Mains conductors carry enough energy to kill you and to start a fire. If you are not qualified to work in a live panel, stop and hire an electrician. The software will still be here when they have finished. Everything from Step 3 onward is safe desk work.
You can try the whole thing first, with no hardware at all. Before buying or wiring anything, run the demo: it generates a fake week of data and runs the complete application against it. Jump to Step 0. If you do not like the software, you have lost ten minutes instead of a weekend.

What You Are Building

Current clamps on your breakers feed one or two meters. The meters talk serial to a small Linux box, which stores everything locally and serves a dashboard. Nothing leaves your house.

You needNotes
ECM-1240 ×1 or ×2 Seven channels each. Each meter needs its own 12 VAC transformer — this powers it AND is its voltage reference.
Current transformers One per circuit you want to see. Sized to the circuit: small split-core for branches, larger (e.g. SPLIT-200) for service conductors.
Serial link RS-232 from each meter to the host. Cat5 works well for the run. Give each meter its own cable and its own USB adapter.
USB serial adapters One per meter. FTDI-based adapters are markedly more reliable than cheap PL2303 clones, which wedge under sustained use.
Host Any Linux machine; a Raspberry Pi is plenty. Plus a USB SSD or spare drive for the database — an SD card will wear out at a 5-second write cadence.
True-RMS clamp meter Borrow one if you must. Without it you cannot verify calibration, and an uncalibrated monitor is confidently wrong rather than obviously broken.

Step 0 — Try It With No Hardware

Ten minutes, no risk, no purchase. Do this first.

git clone https://github.com/Verohomie/ecm1240-monitor.git
cd ecm1240-monitor
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python3 tools/make_demo_data.py --db demo.db --days 7
python3 -m ecm1240.api --config config.demo.yaml

Open http://127.0.0.1:8080/. That is the entire application running on synthesised data. Click the whole-house figure, drag across the chart to zoom, drag the strip to pan. If you want insights in the demo too: 

python3 -m ecm1240.insights --config config.demo.yaml

Step 1 — The Electrical Work

Hire an electrician unless you are genuinely qualified
There is no shame in it, and the rest of this guide does not care who did the wiring.
SeverityRule
DESTROYS 12 VAC, never 12 VDC. A DC supply with the same barrel plug and the same rating will destroy the board. The AC transformer is also how the meter measures voltage — with DC it cannot compute watts even if it survived.
DESTROYS Never power up a meter while holding F1. That erases the CT calibration, and you will not know until the numbers are wrong.
CARE Clamp direction matters. CTs are directional; backwards gives negative or nonsensical readings. Most have an arrow indicating current flow toward the load.
CARE Close the clamp fully until it clicks. A partly-closed core reads low, consistently, and looks like a calibration problem forever.
CARE One conductor per clamp. Clamping both the hot and the neutral together nets to roughly zero, because the currents oppose.
DO Write down which CT went on which breaker, as you go. Take a photo of the panel with labels. Reconstructing this later means turning breakers off one at a time and watching the graph.
DO For whole-house on a split-phase service, clamp BOTH legs. One leg is half your house, and it will look plausible.
DO Run a separate cable per meter back to the host. Sharing one line between two meters causes collisions and makes them impossible to tell apart.

Step 2 — Prove the Meters Are Talking

Before configuring anything, confirm packets are arriving.

ls -l /dev/serial/by-path/          # what did the adapters enumerate as?
python3 tools/ecm_sniff.py /dev/ttyUSB0
Nothing at all? Do NOT assume the meter is dead
This is the most common problem with an ECM-1240, and it is not a fault. A meter with real-time mode switched off never sends a packet — but it is alive and will still answer a direct poll. It is indistinguishable from a dead board, and people have replaced perfectly good meters over it. Two commands rule it out: 
python3 tools/ecm_poll.py /dev/ttyUSB0 -v          # does it answer a poll?
python3 tools/ecm_realtime.py /dev/ttyUSB0 --on   # if yes, switch streaming back on

You should see a line per packet with volts, amps and derived watts. If you see nothing at all, work through this before suspecting the hardware:

SymptomWhat to do
Total silence Real-time mode is off — see the banner above. If a poll gets no answer either, check the 12 VAC supply, then the cable, then whether another program is holding the serial port.
No device in /dev/serial/ The adapter is not enumerating. dmesg | tail after unplugging and replugging tells you whether the kernel sees it.
Garbage or bad checksums Wrong baud (must be 19200 8N1), or a marginal cable. A few bad checksums an hour is normal; a constant stream of them is not.
"Permission denied" Your user is not in the dialout group: sudo usermod -aG dialout $USER, then log out and back in.
"Device busy" Something else holds the port — usually the collector. sudo systemctl stop ecm1240-collector.

Step 3 — Configure

cp config.example.yaml config.yaml
nano config.yaml
Use /dev/serial/by-path/ names, never /dev/ttyUSB0
Every ECM-1240 reports unit_id=0 in its packets no matter how it is configured, so the ONLY way to tell two meters apart is which port each is plugged into. ttyUSB numbering changes between reboots, and cheap adapters report no serial number so by-id names collide. If the two swap, one meter's counters get subtracted from the other's and every reading afterwards is wrong — with no error message and no visible symptom.

The parts you must change

PrioritySettingWhat to do
REQUIRED meters[].port The by-path name for each meter. The program refuses to start while this still says CHANGE-ME.
REQUIRED meters[].channels Name each channel for the circuit its CT is on. Delete channels you are not using. Mark the whole-house channel role: "mains".
IMPORTANT database.path Point it at your SSD, not the SD card.
IMPORTANT unmetered.max_watts Must be higher than your largest circuit with no CT on it. An EV charger draws ~14 kW; too low a value silently rejects real readings for hours. See the trap below.
SET site.rate_per_kwh Your electricity rate, so the cost figures mean something.
LEAVE calibration Leave empty until you have measured with a clamp meter. See Step 5.
LEAVE api.bind Leave at 127.0.0.1 for now. Widen it deliberately later, after reading the security section.

The unmetered-load trap, in plain terms

The collector sanity-checks the whole-house reading against the sum of the individual circuits. If the mains claims far more than the circuits add up to, something is wrong — normally a failing sensor — so the reading is thrown away.

But if you have a big load with no clamp on it — an EV charger, a subpanel added later — then the mains legitimately exceeds the sum whenever it runs. Set unmetered.max_watts above that load, or the monitor will discard hours of perfectly real data every time the car charges. The classic symptom is "my readings vanish at the same time every evening."

Step 4 — First Run

python3 -m ecm1240.collector --dry-run     # decode and log, write nothing

Watch for a minute. Every meter should log a line per packet with sensible volts (around 120 V or 240 V depending on your service) and watts that respond when you switch something on. Turn on a kettle and watch the right circuit move. That single check catches most CT-to-channel mix-ups.

When it looks right, drop the flag and let it write:

python3 -m ecm1240.collector             # in one terminal
python3 -m ecm1240.api                   # in another

Open http://127.0.0.1:8080/.

Step 5 — Calibrate (Do Not Skip)

An energy monitor that is wrong looks exactly like one that is right. There is no error, no gap in the graph — just believable numbers that happen to be false. Full detail is in docs/CALIBRATION.md; the short version:

  • FIRST Read back what the meter thinks its CTs are. python3 tools/ecm_settings.py /dev/ttyUSB0 prints the stored CT type and range per channel. A frequent real-world fault is mains CTs programmed with a smaller CT's setting, so the channel reports exactly half the truth — an entirely believable number.
  • THEN Measure against a clamp meter. Put a big steady load on a circuit, clamp the same conductor, compare. Do it at two load levels — a CT right at 5 A but wrong at 30 A has a different problem from one off by a constant factor.
  • MAINS On a split-phase service, measure BOTH legs and add them before comparing to a whole-house channel. Comparing one leg to a two-leg total is how people convince themselves of a factor-of-two error that is not there.
  • TRAP Correct it in the meter OR in calibration: — never both. Doing both applies the fix twice: a channel reading half now reads double, a four-fold error from where you started, and it will still look like a plausible house. If you reprogram the meter, delete the config entry in the same sitting.
  • CHECK Compare a month against your utility bill. The best end-to-end check available, and it needs no equipment.

Step 6 — Make It Permanent

sudo mkdir -p /opt/ecm1240 /var/lib/ecm1240 /etc/ecm1240
sudo useradd -r -s /usr/sbin/nologin ecm
sudo usermod -aG dialout ecm            # permission to read serial ports
sudo chown -R ecm /var/lib/ecm1240

git clone https://github.com/Verohomie/ecm1240-monitor.git /opt/ecm1240
cd /opt/ecm1240 && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
sudo cp config.yaml /etc/ecm1240/config.yaml

sudo cp systemd/*.service systemd/*.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ecm1240-collector ecm1240-api
sudo systemctl enable --now ecm1240-insights.timer

journalctl -fu ecm1240-collector

Forgetting dialout is the usual reason a service cannot open a port that worked fine by hand.

Friendly device names (optional)

# /etc/udev/rules.d/99-ecm1240.rules
SUBSYSTEM=="tty", KERNELS=="1-1.2:1.0", SYMLINK+="ecm-a"
SUBSYSTEM=="tty", KERNELS=="1-1.3:1.0", SYMLINK+="ecm-b"

Key the rule on KERNELS — the physical port — not on vendor/product id. Two identical adapters cannot be told apart by id, which is the whole reason identity comes from the port in the first place.

Step 7 — Turn On Insights (After a Few Days)

Insights need to know what "running" means for each of your circuits, and those numbers depend on your appliances. Rather than shipping someone else's thresholds, the tool works yours out from your own recorded data. Let it log for at least a few days first — a week is better. 

python3 tools/suggest_profiles.py --explain > profiles.yaml

It builds a histogram of each circuit's watts, finds the empty gap between "off" and "running", and puts the thresholds there — then classifies each circuit from how it behaves over time. --explain annotates each entry with the evidence.

Read the result before trusting it. It knows that a channel has two states about 650 W apart. It does not know that channel is your pool pump. Rename things, fix anything odd, delete circuits you do not care about.

Step 8 — Backups and Security

# /etc/cron.d/ecm1240-backup
17 3 * * * ecm sqlite3 /var/lib/ecm1240/energy.db ".backup '/var/lib/ecm1240/energy-backup.db'"

Use .backup, not cp — copying a file while it is being written produces a corrupt snapshot. Then rsync the backup somewhere else.

Your energy database shows when your house is empty
A per-circuit record sampled every five seconds reveals when people get up, when they go to bed, when nobody is home and when you went away. There is no authentication anywhere in this project — network placement is the only access control. Do not port-forward it. Use a VPN if you want access from outside. The backup is exactly as sensitive as the original.

Commissioning Checklist

Before you call it done

  • Every channel responds. Switch a known load on each circuit and watch the right card move.
  • Whole-house is bigger than the sum of the branches, by roughly the load of circuits without CTs. If it is smaller, something is wrong.
  • Calibration verified against a clamp meter at two load levels.
  • python3 tools/verify_unit_identity.py — the fingerprints match the circuits you assigned.
  • Reboot the host, then check the meters still map correctly. This is what catches unstable port names.
  • curl -s localhost:8080/api/discards — a handful is fine, a flood means a guard is firing constantly.
  • The database is on real storage, not the SD card.
  • A backup has actually run, and you have restored it once to be sure.
  • You wrote down which CT is on which breaker, somewhere you will find it in two years.
